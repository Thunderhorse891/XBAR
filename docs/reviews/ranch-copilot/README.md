## Contract

One horse's existing workspace-scoped record and directly linked active documents produce a read-only, deterministic prioritized plan. Canonical source identity inspection, duplicate review, sale readiness and expiry functions are reused. Identity/reading holds cannot establish reviewed dates or fill gaps. Each suggestion links to the relevant structured record excerpt; missing evidence explicitly means absent within this limited scope. Source text is untrusted data and has no agent/tool execution channel. There is no model integration and the UI explicitly says rule-based.

Build action plan → inspect supporting record excerpts → prepare draft checklist → discard/close. Drafts remain React view state, without store writes, external requests, task creation, outreach, sharing or sale-packet approval. Normal downstream XBAR workflows retain their own permissions and approval gates. Care history, unlinked intake, registry verification and legal/veterinary suitability are outside this plan. Drafts update from the current supplied snapshot; switching horses remounts the card. Closing/reloading discards the view.

The profile card inherits the existing authenticated workspace boundary; the planner performs no retrieval or service-role access. Horse-ID filtering is a second scope check, not a replacement for tenant authorization. The public /app/copilot-demo route imports only explicitly fictional constants, never a customer store. Its review date is fixed and displayed. It does not seed fictional records into a ranch.
