## Confirmed metadata concern and smallest existing fix

Live function definitions and ACLs match repository baseline bodies for `xbar_commercial_limits`, `xbar_subscription_limits`, `xbar_workspace_storage_bytes`, `xbar_has_workspace_access`, `xbar_has_workspace_capability` and `xbar_record_exists` (whitespace/comments normalized). The first three execute as definer and accept arbitrary workspace UUIDs without membership checks. This establishes a code/ACL concern; no customer rows were queried and no customer exposure was simulated against production.

Fictional PGlite/PostgreSQL reproduction returned a foreign workspace's Enterprise limits and99 stored bytes. This is metadata exposure, not evidence of document-content disclosure. Existing draft https://github.com/Thunderhorse891/XBAR/pull/395 already contains the appropriately narrow migration `20261112090000_guard_workspace_metadata_rpcs.sql` at1ce863053686781c7f8a2c402f4481a5ff346c07:

- Revoke direct PUBLIC/anon/authenticated calls to the two internal calculators, retaining service-role and definer-trigger use. Do not add membership checks inside those calculators: real seat enforcement runs before invitation membership exists.
- Scope-check the client-facing storage aggregation with the canonical workspace-access helper or service-role identity, retaining required client/service grants.

The first local alternative added membership guards inside internal calculators. It was withdrawn before commit/push/application because it would break that pre-membership path. Its files are retired outside this branch and must not be applied.

This local branch reuses #395's exact four-file patch on current main. Its old required CI failed an unchanged runbook-coverage assertion because README omitted the proposed migration. README now supplies an explicitly approval-gated command. The RPC drift verifier also expected the newly forbidden calculator grants; new failing tests established that mismatch, then the verifier was aligned to require service grants and reject direct authenticated calculator access. This strengthens the intended boundary rather than weakening an assertion.
