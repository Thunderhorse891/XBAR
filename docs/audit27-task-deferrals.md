# Browser-local Care Tasks deferrals (audit 27)

This is a bounded correction to the live task workflow. Full workspace/cross-device task persistence remains open and requires separate schema/security approval. No SQL or cloud task-state activation is included.

## Contract

- Snooze writes and verifies an actual return date; Dismiss today is labelled accurately. Neither action mutates or marks its source record complete, and neither emits task-completed telemetry.
- Independent task keys include exact workspace/member identity (or the local workspace creation identity). Unrelated tab writes/restores cannot overwrite each other. Same-task browser preferences remain last-write-wins; browser storage is not a database transaction.
- Snapshot-only recovery uses the cloud store's verified recovery ranch only when its user matches the current session. Missing/null or foreign-user recovery context stays in a distinct account-only scope; source metadata from imported backups does not establish ranch identity. Returning to the same verified ranch restores its own preferences. This changes task scope only, never the file-vault namespace.
- Failed saves keep work visible. Multi-task restore reports only confirmed progress when a later write fails. Unreadable/malformed data cannot hide work indefinitely.
- Observed revision changes or disappearance clear only that task's saved snooze with verified readback, so reverting the source cannot silently reactivate it. Group-filter changes do not count as disappeared work. Source history never observed by this tab cannot be inferred. A stale tab can conservatively resurface a newer same-task snooze; unrelated keys are preserved. If cleanup or reading cannot be verified, a tab-lifetime, scope-isolated fail-open latch ignores deferrals and refuses new snoozes until reload. One inline notice explains that unsuccessful cleanup may leave older deferrals on disk, which can return after reload. No cleanup success is claimed on failure.
- Source fingerprints reveal changed care, ownership, document or buyer work, including reassigned buyer horses and same-day offer/deposit updates. Canonical useDayKey refreshes the board at local rollover and after clock/timezone changes. A valid week-long snooze tolerates westward date-line travel.
- Today excludes future and closed buyer follow-ups. HerdGroups and /today?segment retain the selected group for all four task sources. Archived horses are omitted. Queued documents open Processing, and review routes retain their horse.
- Native buttons provide keyboard actions without nested clickable rows. Scoped responsive CSS wraps long task text. Group and category filters share one sticky region so the group control remains reachable after scrolling. Changed or removed drawer selections are cleared permanently; reverting source values does not reopen a dismissed drawer.

## Verification and recovery

The current-main task derivation was reproduced with a buyer due in 2099: it appeared in Today. The original Snooze callback only toasted and closed; Mark Done emitted completion before hiding a task locally. Twenty-one behavior tests cover the corrected contract, including deliberate cross-tab interleavings, partial storage failures, and offer/deposit updates with unchanged stage and last-touch day. The offer/deposit and revision-reversion regressions both failed on their reviewed candidates before correction. Invalidation tests cover refused/silent writes, refused readback, same-task races, different-task preservation, observed disappearance and reload limits. Browser specs cover snooze/reload/expiry, source reversion, cleanup refusal across route remounts, group history, refusal, keyboard navigation and long mobile content.

This implementation was reconstructed after the execution workspace lost the previously reviewed local-only patch. It is a new candidate against main 356084b779f67654b17a2aa5fea21d6b8f0062ea, not a recovered copy of that old commit. Existing PR305 history is retained when updating the branch; its earlier device-global helper/tests are superseded by the scoped behavior suite.

No local rendered/browser pass is claimed. Three added browser regressions cover source-change/reversion and desktop/mobile scrolled filter hit targets. Their local reproduction attempt was blocked; the underlying source paths match the review findings. Exact-head remote CI and final-head independent review remain release gates; passing build/Node checks alone is not workflow verification.
