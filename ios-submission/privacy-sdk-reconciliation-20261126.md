## Google Auth finding

The current candidate has **no** `@codetrix-studio/capacitor-google-auth` dependency in `package.json` or `package-lock.json`, no GoogleAuth/GoogleSignIn/GIDSignIn references in the tracked iOS project or Swift package graph, and no native third-party sign-in buttons. `ios/App/CapApp-SPM/Package.swift` links Capacitor/Cordova 8.5.1, CapacitorFilesystem 8.1.3 and CapacitorShare 8.0.1. The actual `f3e2e41` native build log resolves and compiles Filesystem and Share; this is stronger than an npm inventory, but does not by itself establish the absence of every static symbol in a binary.

The Filesystem package also declares the transitive `IONFilesystemLib` package. The actual `f3e2e41` build log resolves `ion-ios-filesystem` **1.1.4** and compiles that target. Include it in final SDK/privacy review; top-level npm names alone omit this dependency. No standalone `.xcprivacy` file was found in the installed Filesystem or Share npm package trees; that does not certify their accessed APIs or the transitive library's manifest.

The native workflow now retains `native-build-inventory.json` from the actual compiled unsigned device `.app`: bundle identity/version/build, binary hash, Capacitor plugin classes, embedded frameworks, linked libraries, bounded SDK-symbol matches and every packaged privacy manifest. Inspect its exact-head result before claiming compiled absence. Google OAuth web/server configuration and text referring existing Google users to email-code sign-in do not establish that a Google native SDK is linked. No installed App Store build or signed archive is accessible, so neither is claimed inspected. Do not remove a package that is absent or certify privacy labels from package names alone.
